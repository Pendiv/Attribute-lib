 attributelib 企画書
 作成日: 2026-06-12
 対象環境: Paper 26.1.2 / Java 25(専用、後方互換は考慮しない)
================================================================

■ 1. 目的

MOD環境(Forge attribute / L2DamageTracker相当)の使い勝手をPaperに
持ち込む基盤ライブラリを作る。提供するのは三本柱:

 1) カスタム属性の登録・計算
    任意のプラグインが register(plugin, "dodge_chance", base) で
    新属性を追加でき、操作は1行で完結する
 2) ダメージ種別と計算パイプライン
    物理/魔法/確定ダメージ、会心、防御貫通を、順序の保証された
    一本の計算系で扱う
 3) 武器防具への安定表示・添付の共通システム
    属性をアイテムに付与し、tooltipに安定して表示する

■ 2. 背景

EnhancedMobs(モブ強化+装備強化、トレイト151種)の拡張で、
ステータス操作の散在が工数の主因になっている。
バニラ属性ヘルパー(Mobs.addModifier)と疑似属性の単発実装
(HealMultiplier、コメントに本構想の原型あり)が既に存在し、
本libはこれらの汎用化にあたる。新規技術要素はなく、要素技術は
すべてコードベース内か公式APIで実証済み。

■ 3. 構成(4層)

【層1: 属性エンジン】
 属性の登録・取得・モディファイア管理(恒久/時限)。
 エンティティPDCに保持。NamespacedKeyが登録元プラグイン
 名前空間になるため衝突しない。イベントには触れない純粋部分。

【層2: ダメージパイプライン+標準属性】
 与ダメ/被ダメ/種別倍率/会心/回復倍率等の「適用リスナー」を
 サーバーに1つだけ提供。二重処理を構造的に防ぐ。

【層3: 装備同期】
 アイテムに書かれた属性をエンティティへ反映。
 バニラ属性分は attribute_modifiers コンポーネントに書くだけ
 (同期はバニラが行う)。カスタム属性分のみ自前の再計算ループ
 (メモリ保持)。

【層4: 表示】
 バニラ属性は AttributeModifierDisplay(1.21.5+)の override で
 緑文字を自前デザインに置換(クライアント描画、lore非汚染)。
 カスタム属性はlore行で表示し、lore書き込みはコンポーザー
 1箇所に集約する。

■ 4. 標準属性(対構造)

  攻撃側                          | 防御側
 --------------------------------+--------------------------------
  damage_dealt(全与ダメ%)        | damage_taken(全被ダメ%)
  physical_damage%                | physical_resist%
  magic_damage%                   | magic_resist%
  crit_chance / crit_damage       | (任意: crit_resist)
  armor_penetration(率/値)       | バニラ armor
  確定ダメージ                    | 対なし(定義)
  heal_multiplier(回復倍率、     | —
   HealMultiplier吸収)           |

 採掘速度はバニラ属性(BLOCK_BREAK_SPEED / MINING_EFFICIENCY /
 SUBMERGED_MINING_SPEED)が既に存在するため層1のファサードで
 包むのみ。自作不要。

■ 5. ダメージ種別設計(26.1.2専用)

 データパックでカスタムダメージタイプを定義し、バニラの
 ダメージタイプタグで防御との相互作用を宣言する。

 ・attributelib:physical_pierce
    tags: bypasses_armor のみ
    → バニラ防具は素通り、物理軽減%は効く
      (自前リスナーがカテゴリ判定で適用)

 ・attributelib:true_damage
    tags: bypasses_armor + effects + enchantments
          + resistance + invulnerability
    → バニラ防御全素通り+自前リスナーも何もしない
      =入力値がそのまま通る。
      invulnerability付きのため無敵フレームに食われない。

 ・attributelib:magic
    魔法カテゴリ。バニラタグは設計時に選定。

 能動API: DamageLib.magic(attacker, victim, 8) 等。
 DamageSource.builder でカスタムタイプを指定して撃つ。
 被害者側リスナーは event.getDamageSource() でタイプを読むため、
 能動・受動・他プラグイン由来を同一系で処理できる。

■ 6. 計算パイプライン

 単一リスナー(優先度固定)で

   種別倍率 → 会心 → (部分貫通の防御再計算) → 全体倍率

 の順に final 目標値 F' を算出し、setDamage(B × F'/F) の
 比例再スケールで着地させる。
 非推奨の DamageModifier API には依存しない。

■ 7. 開発方針

 ・Gradleの :attributelib モジュールとして完全分離
   (ホスト参照ゼロ、登録時Plugin引数必須)。
   当面EnhancedMobsと同jar出荷、利用プラグインが増えた時点で
   独立jar昇格。
 ・段階リリース: 層1 → 2 → 3 → 4。各層単体で価値が出る。
 ・EnhancedMobs側は既存トレイトのsetDamage直叩きを属性書き込みへ
   漸進移行。スキルAPI再設計のapplyStatsフックは本libの
   1行呼び出しになる。

■ 8. 既知のリスクと対策

 1) 部分貫通(貫通50%等)はタグで表現不可
    → バニラ防御式の自前再計算。式は公開済みだが要テスト
 2) 死亡メッセージ: カスタムタイプは翻訳キー欠落で生キー表示
    → message_id をバニラ既存(magic等)に流用
 3) デプロイ: ダメージタイプはワールドロード時読込
    → jarから world/datapacks へ自動コピー、初回のみ再起動1回
 4) PDC永続化の裏目: 装備由来モディファイアはPDCに書かない
    (ゴースト強化防止)。メモリ+再計算方式
 5) 時限処理: Bukkit.getCurrentTick() は再起動でリセット
    → ワールド時間基準(HealMultiplier吸収時に既存バグも修正)
 6) トレイト移行期の二重取り: 旧setDamage方式と新属性の
    併用禁止規約を移行ガイドに明記
 7) 小物: バニラジャンプ会心との重複(isCriticalで検出)/
    負ダメージのクランプ/エンティティアンロード時のキャッシュ掃除

■ 9. スコープ外(意図的に落としたもの)

 ・ブロック種別ごとの採掘速度制御(工数が別次元のため)
 ・属性相性表(火水風土等)
   → 種別タグを文字列で拡張可能な設計にのみしておき、
     実装は需要が出てから
