# ディレクトリ構造

> 先頭が _ になっているものは使用予定はないが参考元とするために残しているもの。将来的に削除予定

### register

各要素をまとめて管理する場所です。
ここでは基本的に[util](#util)の `ClassUtils`のメソッドを使用して、特定のパッケージからサブクラスを自動で抽出して登録しています。

### util

Utilityなstaticメソッドまとめ。

### listener

BukkitのListenerを配置しています。
今後違うlistenerも作る場合はその中にbukkit, ... などでディレクトリを分けてください。

### loader

Configをロードして何かをする系のコード。
現在はKTSを使用したアイテムの登録コードが配置してあります。

### di

GuiceのDependencyInjectionに使用する情報を登録するクラス。

### data

アイテムやスキルなど、抽象クラスを実装したデータを配置します。

### core

実際の処理や、データの抽象クラスを作成する。
詳細は[core内部](#core内部)を確認してください。

### command

コマンドの処理を書きます。
各コマンドごとにこの中に更にディレクトリを作ってください。
また、そのコマンドが巨大な場合は各サブコマンドごとにファイルを分けるなどして、可読性を保つようにしてください。

# core内部

- core内部には、dataで使用するためのベースとなる抽象クラスを配置する場所である `base`と、実際の処理を行う `system`を作成してください。
- dataでの項目がない場合は `base`と `sysmte`は作成せず、`system`の項目をそのフォルダに直接書きます。
